# macOS Desktop App (Tauri v2 + Node sidecar) — Spec

> Written by `create-feature`. Lives at `context/features/macos-desktop-app-spec.md`.
> Archived to `context/features/completed/` on `feature complete`.

## Problem

Readbook today is a local web app: you run `pnpm dev`, remember port 4321, and read in a
browser tab surrounded by every other tab you were trying to escape. That contradicts the
whole product thesis — "one calm, distraction-free reading experience, your shelf." A
read-it-later app that lives in a browser tab is competing with the noise it exists to remove.

This feature packages Readbook as a real macOS `.app`: dock icon, own window, no address bar,
no neighbouring tabs, launches without a terminal. Tauri v2 is chosen over Electron because it
uses the system WKWebView instead of bundling Chromium — a ~10MB shell and ~80MB idle RAM
instead of ~150MB and ~300MB. For a typography-obsessed reading app, WKWebView is also the
*better* renderer on macOS: native text rendering and system font smoothing.

The backend stays exactly as-is. Astro SSR, Drizzle over better-sqlite3, and the hybrid
extractor are compiled into a single self-contained binary and shipped as a Tauri **sidecar**
process. Zero rewrite of `packages/*`, and the Cloudflare/D1 direction stays open because
nothing about the `Reading` contract or the server-endpoint architecture changes.

## Users

The single owner/reader. No new personas — this is the same one reader, on their Mac, without
a terminal or a browser in the way.

## Goals

- [ ] `Readbook.app` launches from Finder/Spotlight and shows the feed — no terminal, no `pnpm dev`
- [ ] The app is self-contained: it does not read from or depend on the repo checkout at runtime
- [ ] The reading DB lives at `~/Library/Application Support/Readbook/readbook.db` and survives rebuilds
- [ ] Bundle size stays under ~120MB; idle RSS (shell + sidecar) stays under ~250MB
- [ ] Zero changes to `packages/core`, `packages/db`, and `packages/extractor` source logic
- [ ] `FIRECRAWL_API_KEY` is configurable from inside the app — no `.env` file required
- [ ] `pnpm dev` still works unchanged for browser-based development

## Flow

### Build-time

1. `pnpm build` produces the Astro standalone server at `apps/web/dist/server/entry.mjs`.
2. `scripts/build-sidecar.mjs` compiles that server plus its runtime deps into ONE executable,
   emitted to `apps/desktop/src-tauri/binaries/readbook-server-aarch64-apple-darwin`
   (Tauri requires the target-triple suffix).
3. `tauri build` compiles the Rust shell, embeds the sidecar, and emits
   `apps/desktop/src-tauri/target/release/bundle/macos/Readbook.app`.

### Runtime

1. User opens `Readbook.app`. Rust `main.rs` runs before any window is shown.
2. Shell binds `127.0.0.1:0` to get a free ephemeral port from the OS, then releases it.
   (Hardcoded 4321 is not used — it collides with a running `pnpm dev`.)
3. Shell resolves `app_data_dir()` → `~/Library/Application Support/Readbook/`, creating it if
   absent, and spawns the sidecar with:
   - `PORT=<ephemeral>`, `HOST=127.0.0.1`
   - `READBOOK_DB_PATH=<app_data_dir>/readbook.db`
   - `READBOOK_DATA_DIR=<app_data_dir>`
   - `NODE_ENV=production`
4. Sidecar boots. `apps/web/src/lib/settings.ts` reads `<READBOOK_DATA_DIR>/settings.json` and,
   if a `firecrawlApiKey` is present, assigns it to `process.env.FIRECRAWL_API_KEY`.
   `packages/db` opens `READBOOK_DB_PATH` and runs its existing idempotent `ensureSchema()`.
5. Shell polls `GET http://127.0.0.1:<port>/` every 100ms until a 2xx, max 15s.
6. On ready, the shell creates the main `WebviewWindow` pointed at `http://127.0.0.1:<port>/`.
   Window: 1100×820 default, 640×480 minimum, `titleBarStyle: "Overlay"`, restores last size
   and position. Nothing is shown before this point — no white flash, no half-loaded frame.
7. User reads. Everything below the webview is the app that already exists.
8. On quit (⌘Q, window close, or `RunEvent::ExitRequested`), the shell sends SIGTERM to the
   sidecar and waits up to 3s, then SIGKILL. No orphaned Node processes.

### Firecrawl key flow

1. User opens Settings from the app menu or the header control.
2. `settings.astro` renders a single password field. `GET /api/settings` returns
   `{ hasKey: true, masked: "fc-…a91f" }` — never the full key.
3. User pastes the key, submits. `POST /api/settings` validates the shape, writes
   `settings.json` with mode `0600`, and sets `process.env.FIRECRAWL_API_KEY` in the live
   process so the very next extraction can use it.
4. A "Clear key" action deletes the field from `settings.json` and `delete`s the env var.

### One-time DB migration

Run once, from the repo, before or after the first `.app` launch:

```
pnpm db:migrate-app-support
```

Copies `data/readbook.db` (plus `-wal` / `-shm` if present) to
`~/Library/Application Support/Readbook/`. Refuses to overwrite an existing destination unless
`--force` is passed. Prints what it did. The repo copy is left in place, untouched, so
`pnpm dev` keeps working against it.

## Acceptance criteria

- [ ] `pnpm desktop:build` produces `Readbook.app`; it opens by double-click and shows the feed
- [ ] `.app` bundle size ≤ 120MB; `du -sh Readbook.app` recorded in the history entry
- [ ] Idle RSS of shell + sidecar combined ≤ 250MB, measured with Activity Monitor after 60s
- [ ] Cold launch to first painted feed ≤ 3s on the target machine
- [ ] Pasting a URL in the packaged app extracts, stores, and renders — full round-trip
- [ ] The reader renders identically in WKWebView to Chrome/Safari: serif body, ~66ch measure,
      light/sepia/dark all correct, font-size control works, scroll progress resumes
- [ ] App runs with `pnpm dev` also running — no port conflict, two independent DBs
- [ ] `lsof -p <sidecar-pid>` confirms the DB opened is the App Support path, not `data/`
- [ ] Quitting the app leaves no `readbook-server` process (`pgrep -f readbook-server` is empty)
- [ ] With no key configured, an X/Twitter URL fails with the existing `ExtractionError` message
      surfaced in the UI — not a blank page or an unhandled 500
- [ ] After saving a key in Settings, the same X/Twitter URL succeeds without restarting the app
- [ ] `settings.json` is mode `0600`; `GET /api/settings` never returns the unmasked key
- [ ] `pnpm db:migrate-app-support` copies the DB and the packaged app shows those readings
- [ ] `pnpm build`, `pnpm typecheck`, and `pnpm lint` all pass green
- [ ] Deleting the repo checkout does not break the installed `.app`

## Edge cases

- **better-sqlite3 in a compiled binary** — the native `.node` addon uses a `__filename`-based
  binding loader that single-file bundlers routinely break. This is the single highest-risk item
  in the feature and is handled by a spike gate; see *Implementation order* below.
- **Port exhaustion / race** — the ephemeral port is bound-then-released, so another process can
  in principle claim it in the gap. If the sidecar fails to bind, it exits non-zero; the shell
  retries the whole allocate-and-spawn cycle up to 3 times before surfacing an error.
- **Sidecar never becomes healthy** — after the 15s poll timeout, show a native error dialog with
  the sidecar's captured stdout/stderr tail, then quit. Never leave a blank window.
- **Sidecar crashes mid-session** — the shell watches the child. On unexpected exit, show a
  dialog offering Relaunch or Quit. Do not silently show a dead webview.
- **Two instances launched** — Tauri single-instance plugin: focus the existing window instead of
  spawning a second sidecar and a second SQLite writer.
- **Existing WAL files** — the migration script must copy `-wal` and `-shm` alongside the `.db`,
  or checkpoint first. A `.db` copied without its WAL silently loses recent writes.
- **First run, no DB** — `ensureSchema()` already handles this; the feed must render its empty
  state, not an error.
- **App Support dir not writable** — surface a native dialog naming the path; do not fall back to
  a temp dir and silently lose data.
- **Gatekeeper on first open** — unsigned build. First launch needs right-click → Open, or
  `xattr -dr com.apple.quarantine`. Documented in `AGENTS.md`, not worked around in code.
- **Offline** — Readability fetch fails with a network error. Existing `ExtractionError` path
  applies; already-stored readings must still open (they are local HTML).
- **Malformed / whitespace-only key** — rejected client- and server-side; `settings.json` is never
  written with an empty-string key, which would shadow a real env var.
- **`.env` still present in dev** — `astro.config.mjs` `loadEnvFile` runs at dev/build time only.
  Precedence in the packaged app: `settings.json` wins, since no `.env` ships in the bundle.
- **External links in the reader** — a link inside article HTML must open in the system browser,
  not navigate the app webview away from `localhost`. Intercept and route to `shell.open`.

## Out of scope

- **Code signing, notarization, DMG, auto-update** — local unsigned build only, per decision.
  A signed/notarized distribution is a separate spec.
- **Share extension** (Safari → Readbook) — needs a native Swift app-extension target.
- **Global hotkey quick-capture** and **menu bar / tray item** — follow-up specs.
- **Keychain storage for the Firecrawl key** — `settings.json` at `0600` for now. Noted as a
  known weakness (see Constraints), not solved here.
- **Windows / Linux builds** — macOS `aarch64` only. Do not add other targets.
- **The Path B Rust rewrite** — porting `db`/`extractor` to `rusqlite`/`dom_smoothie`/`ammonia`
  would land ~12MB, but it is a separate, much larger spec. Not now.
- **Cloudflare Workers + D1** — remains off limits.
- **Offline reading, search, tags, highlights, RSS** — unchanged roadmap items.
- **Any redesign of the feed or reader UI** beyond the new Settings screen.

## Constraints

- **No version bumps.** Astro `7.0.2`, `@astrojs/node` `11.0.0`, Drizzle `0.45.2`,
  better-sqlite3 `12.11.1`, TypeScript `5.9.3`, Turborepo `2.10.0`, pnpm `10.32.1`, Node `>=22`
  all stay pinned. Tauri v2 and its Rust toolchain are additive.
- **New toolchain prerequisites:** Rust stable + Xcode Command Line Tools. If the sidecar spike
  picks Bun, Bun becomes a build-time-only dependency — it must never be required to *run* the app.
- **`packages/*` logic is not to be modified.** If the desktop build needs a behavioural change in
  `db` or `extractor`, stop and propose it rather than editing under this spec.
- **Sanitization stays non-negotiable.** WKWebView is not a weaker sandbox, but nothing about the
  `sanitize-html` path changes, and no new HTML sink is introduced.
- **The sidecar binds `127.0.0.1` only.** Never `0.0.0.0` — this must not become a LAN service.
- **Security tradeoff, stated plainly:** the Firecrawl key is stored in plaintext in
  `~/Library/Application Support/Readbook/settings.json` at mode `0600`. That protects it from
  other users on the machine, but not from any process running as you. Acceptable for a
  single-user local app with a low-value revocable key; migrating to the macOS Keychain is the
  correct follow-up.
- **Accessibility:** the Settings screen inherits existing theme tokens and must be keyboard-
  navigable with visible focus rings and a labelled input. The window must respect the system
  Reduce Motion setting the same way the web app does.
- **Branch:** `feature/macos-desktop-app` off `main`. Commit only on a green build + typecheck,
  and only with explicit permission.

## Implementation order

**Step 0 — sidecar spike (gate; do this before anything else).**
The whole feature rests on getting `entry.mjs` + better-sqlite3 into a runnable single artifact.
Time-box it. Try in order, stop at the first that works:

- **A. `bun build --compile`** — smallest single binary (~60MB). Verify it can actually open a
  SQLite DB and complete one full paste→extract→store→render cycle. If the `.node` binding
  loader breaks under `--compile`, do not fight it. Move to B.
- **B. Node binary sidecar + resources** — ship the official `node` arm64 binary as the Tauri
  sidecar and `entry.mjs` + `node_modules/better-sqlite3` as bundled resources; the shell invokes
  `node entry.mjs`. Larger (~110MB) and boringly reliable, because the addon stays a real file on
  disk. This is the fallback and it is fine.

Record which path was chosen, the measured bundle size, and why, in the history entry. Only then
proceed to the Tauri shell, then Settings, then the migration script.

## Open risks

- Bundle size is the loosest number here. If the spike lands on option B, ~110MB is the realistic
  floor — still well under Electron, but the "12MB app" only exists on the Path B Rust rewrite.
- WKWebView renders text differently from Chromium. The reader's measure and rhythm were tuned in
  a browser; expect small typography adjustments, and treat the visual acceptance criterion above
  as a real review step rather than a checkbox.
